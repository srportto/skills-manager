## Saída bruta

### Motivo (smells concretos)
- `despachar()` mistura decidir elegibilidade, capturar dados do registro, marcar estado e submeter ao worker (Long Method).
- `aplicar()` e `aoRevogar()` acumulam duas responsabilidades cada (confirmar x falhar; esperar x commitar).
- `ciclo()` tem um loop de enfileiramento embutido; `ajustarPausas()` repete a condição "tem trabalho" inline.
- Literais `10` (segundos) soltos no construtor e no `close()` (Replace Magic Number).

Não mexi em nada que seja design de concorrência (um único thread usa o `Consumer`, fila de conclusões, etc.): não há smell que justifique.

### Código refatorado (trechos que mudam; o restante da classe permanece idêntico)

```java
private static final Duration PRAZO_REVOGACAO_PADRAO = Duration.ofSeconds(10);
private static final long PRAZO_ENCERRAMENTO_SEGUNDOS = 10;

private static final class Estado<V> {
    final ArrayDeque<ConsumerRecord<String, V>> pendentes = new ArrayDeque<>();
    boolean ocupada;
    ConsumerRecord<String, V> emAndamento;
    int tentativas;
    long proximaTentativa;
    Exception ultimoErro;

    boolean temTrabalho() { return ocupada || !pendentes.isEmpty(); }

    boolean prontaParaDespacho(long agora) { return !ocupada && !pendentes.isEmpty() && agora >= proximaTentativa; }
}

// construtor curto: this(..., relogio, PRAZO_REVOGACAO_PADRAO);

public void ciclo(Duration timeoutPoll) {
    drenarConclusoes();
    commitar();
    ajustarPausas();
    enfileirarRecebidos(timeoutPoll);
    despachar();
    ajustarPausas();
}

private void enfileirarRecebidos(Duration timeoutPoll) {
    for (ConsumerRecord<String, V> registro : consumidor.poll(timeoutPoll)) {
        var particao = new TopicPartition(registro.topic(), registro.partition());
        estados.computeIfAbsent(particao, p -> new Estado<>()).pendentes.addLast(registro);
    }
}

private void aplicar(Conclusao<V> conclusao) {
    emVoo--;
    Estado<V> estado = estados.get(conclusao.particao());
    // (comentário original sobre conclusão descartada mantido)
    if (estado == null || estado.emAndamento != conclusao.registro()) return;
    estado.ocupada = false;
    estado.emAndamento = null;
    if (conclusao.resultado().decisao() == ConsumoControlado.Decisao.CONFIRMAR) {
        registrarConfirmacao(estado, conclusao);
        return;
    }
    registrarFalha(estado, conclusao);
}

private void registrarConfirmacao(Estado<V> estado, Conclusao<V> conclusao) {
    estado.pendentes.pollFirst();
    estado.tentativas = 0;
    estado.ultimoErro = null;
    aCommitar.put(conclusao.particao(), new OffsetAndMetadata(conclusao.registro().offset() + 1));
}

private void registrarFalha(Estado<V> estado, Conclusao<V> conclusao) {
    estado.tentativas++;
    estado.ultimoErro = conclusao.resultado().erro();
    estado.proximaTentativa = relogio.getAsLong() + pausaEntreTentativasNanos;
}

private void despachar() {
    long agora = relogio.getAsLong();
    for (var entrada : estados.entrySet()) {
        if (emVoo >= limiteEmVoo) return;
        if (entrada.getValue().prontaParaDespacho(agora)) iniciarTrabalho(entrada.getKey(), entrada.getValue());
    }
}

private void iniciarTrabalho(TopicPartition particao, Estado<V> estado) {
    ConsumerRecord<String, V> registro = estado.pendentes.peekFirst();
    boolean quarentenar = estado.tentativas >= maxTentativas;
    Exception causa = estado.ultimoErro;
    estado.ocupada = true;
    estado.emAndamento = registro;
    emVoo++;
    workers.execute(() -> conclusoes.add(new Conclusao<>(particao, registro,
            quarentenar ? controle.quarentenar(registro, causa) : controle.consumir(registro))));
}

// em ajustarPausas: boolean comTrabalho = estado != null && estado.temTrabalho();

private void aoRevogar(Collection<TopicPartition> particoes) {
    aguardarTrabalhoEmAndamento(particoes);
    commitarERemoverRevogadas(particoes);
}

private void aguardarTrabalhoEmAndamento(Collection<TopicPartition> particoes) {
    long limite = System.nanoTime() + prazoRevogacao.toNanos();
    try {
        while (particoes.stream().map(estados::get).anyMatch(e -> e != null && e.ocupada)) {
            long restante = limite - System.nanoTime();
            if (restante <= 0) break;
            Conclusao<V> conclusao = conclusoes.poll(restante, TimeUnit.NANOSECONDS);
            if (conclusao != null) aplicar(conclusao);
        }
    } catch (InterruptedException erro) {
        Thread.currentThread().interrupt();
    }
}

private void commitarERemoverRevogadas(Collection<TopicPartition> particoes) {
    var revogados = new HashMap<TopicPartition, OffsetAndMetadata>();
    for (TopicPartition particao : particoes) {
        OffsetAndMetadata offset = aCommitar.remove(particao);
        if (offset != null) revogados.put(particao, offset);
        estados.remove(particao);
    }
    if (!revogados.isEmpty()) consumidor.commitSync(revogados);
}

// close(): if (!workers.awaitTermination(PRAZO_ENCERRAMENTO_SEGUNDOS, TimeUnit.SECONDS)) workers.shutdownNow();
```

### Invariantes preservados (conferidos linha a linha)
- Ordem no `ciclo`: drenar -> commitar -> pausas -> poll -> despachar -> pausas (idêntica).
- Ordem por partição: só o `peekFirst` da partição é despachado, uma por vez (`ocupada`); `pollFirst` apenas na confirmação.
- Commit só do concluído e após o efeito: `aCommitar` é preenchido somente em CONFIRMAR e commitado no início do ciclo seguinte, no `aoRevogar` e no `close`; falha do `commitSync` continua deixando `aCommitar` intacto para nova tentativa.
- Em `iniciarTrabalho`, `registro`, `quarentenar` e `causa` são capturados antes de marcar `ocupada`/`emAndamento` e de `emVoo++`, exatamente como antes; o limite `emVoo >= limiteEmVoo` continua checado por iteração.
- Conclusão tardia/de entrega antiga é descartada, mas `emVoo--` roda sempre.
- Revogação: espera limitada por `prazoRevogacao` com `nanoTime`; interrupção restaura a flag e segue para o commit; commit só dos offsets já concluídos; estado removido.
- `close`: shutdown, espera 10 s, `shutdownNow`, drena e commita — igual. Ordem de validação do construtor e mensagens de exceção inalteradas. API pública (assinatura, `emVoo()`, `ciclo`, `assinar`, `close`) inalterada.

### Achados fora do escopo (não alterei, são bugs/riscos — não refactoring)
- `onPartitionsLost` remove `estados`, mas não limpa `aCommitar` das partições perdidas: o próximo `commitar()` pode tentar commitar offset de partição que não pertence mais ao membro (CommitFailedException ou commit obsoleto), contradizendo o comentário do método. Encaminhar ao `java-construtor` com um teste de caracterização antes.
- Os testes atuais (4) não cobrem explicitamente revogação com trabalho em andamento nem `onPartitionsLost`; recomendo caracterizar (latch/relógio injetado, sem sleep) antes de qualquer mudança futura nessas rotas.
