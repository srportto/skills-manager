## Saída bruta

### Escopo e hipóteses

Pedido: repetir a cobrança quando a resposta do gateway de pagamento estoura o timeout. Não vou implementar "repetir às cegas": timeout de resposta **não é rollback remoto** (o gateway pode ter cobrado), então um retry ingênuo gera **cobrança em duplicidade**. A implementação correta é: chave idempotente + consulta/reconciliação do estado remoto antes de repetir + retry limitado dentro de um deadline.

Hipóteses (declaradas, sem perguntar de volta):
- App hexagonal existente (`domain`/`application`/`infrastructure`), Java 25, Spring Boot 4, módulo de pagamentos.
- Gateway externo HTTP que aceita header `Idempotency-Key` e tem consulta por chave (`GET /cobrancas?chave=...`). Se o gateway NÃO suportar nenhum dos dois, o retry automático de cobrança fica **proibido** (o estado vira PENDENTE e segue para reconciliação manual/assíncrona).
- Deadline total da operação lógica: 5 s; timeout por tentativa: 1,5 s; no máximo 3 tentativas (a inicial inclusa); backoff 100 ms a 400 ms com full jitter.
- Esta camada (use case de cobrança) é a **única dona do retry**: o cliente HTTP e o gateway/proxy não repetem (retry do SDK/HTTP client desligado, para não multiplicar 3 x 3 x 3).
- Persistência da tentativa em banco relacional via `port/out` (pendência de infra: tabela `cobranca`).

### Decisões

| Item | Decisão | Motivo |
|---|---|---|
| Chave idempotente | UUID gerado **uma vez** por cobrança lógica e persistido antes da 1ª chamada; reutilizado em todas as tentativas | repetição com a mesma chave não gera efeito duplo no gateway |
| Elegível a retry | só `timeout de leitura/resposta`, `IOException` de rede e 502/503/504 | falha transitória |
| NÃO elegível | recusa de negócio (cartão negado, saldo), 4xx, payload inválido, interrupção, cancelamento | erro permanente ou de negócio: repetir não ajuda |
| Efeito desconhecido | após timeout, **consultar** o gateway pela chave; se `APROVADA`/`RECUSADA`, adota o resultado e não repete; se `NAO_ENCONTRADA`, repete com a mesma chave; se a consulta também falha, estado `PENDENTE_RECONCILIACAO` | timeout não prova que nada foi cobrado |
| Orçamento | deadline monotônico (`System.nanoTime`); não dorme se o backoff consome o restante | tempo limitado, sem espera infinita |
| Fallback | **nenhum que invente sucesso**: sem resposta conclusiva, devolve `PENDENTE`, nunca "aprovada" | pagamento não admite fallback otimista |
| Quem repete | uma camada (use case); retry do SDK desligado | evita amplificação |
| Alternativa rejeitada | retry transparente no `RestClient` | não conhece a chave nem reconcilia; mascara efeito desconhecido |

### Código (trechos relevantes)

Domínio (sem Spring/JPA/Jackson):

```java
package br.com.srportto.pagamentos.domain.model;

// Resultado conclusivo ou pendente de uma cobrança; "pendente" nunca é tratado como sucesso
public sealed interface ResultadoCobranca {
    record Aprovada(String idTransacao) implements ResultadoCobranca {}
    record Recusada(String motivo) implements ResultadoCobranca {}
    record PendenteReconciliacao(String chaveIdempotencia) implements ResultadoCobranca {}
}
```

```java
package br.com.srportto.pagamentos.domain.port.out;

public interface GatewayPagamentoPort {

    // Pode lançar FalhaTransitoriaException (timeout/rede/5xx) ou FalhaPermanenteException (4xx)
    ResultadoCobranca cobrar(Cobranca cobranca, String chaveIdempotencia);

    // Consulta o estado remoto pela chave; vazio = o gateway nunca recebeu a cobrança
    Optional<ResultadoCobranca> consultar(String chaveIdempotencia);
}
```

```java
package br.com.srportto.pagamentos.domain.port.out;

public interface RegistroCobrancaPort {
    // Grava a intenção (chave + payload) ANTES de chamar o gateway; mesmo payload devolve a mesma chave
    String registrarIntencao(Cobranca cobranca);
    void registrarResultado(String chave, ResultadoCobranca resultado);
}
```

Caso de uso (a única camada dona do retry):

```java
package br.com.srportto.pagamentos.application.usecase;

public class CobrarComRetryService implements CobrarUseCase {

    private static final int MAX_TENTATIVAS = 3;            // inclui a chamada inicial
    private static final Duration ATRASO_BASE = Duration.ofMillis(100);
    private static final Duration ATRASO_MAXIMO = Duration.ofMillis(400);

    private final GatewayPagamentoPort gateway;
    private final RegistroCobrancaPort registro;
    private final Duration deadlineTotal;
    private final LongSupplier relogioMonotonico;             // injetável: System::nanoTime
    private final Esperador esperador;                        // injetável: Thread.sleep em produção
    private final DoubleSupplier jitter;                      // injetável: ThreadLocalRandom::nextDouble

    // construtor omitido

    @Override
    public ResultadoCobranca cobrar(Cobranca cobranca) {
        // chave persistida antes de qualquer chamada: reinício do processo reaproveita a mesma chave
        String chave = registro.registrarIntencao(cobranca);
        long limite = relogioMonotonico.getAsLong() + deadlineTotal.toNanos();

        for (int tentativa = 0; tentativa < MAX_TENTATIVAS; tentativa++) {
            try {
                var resultado = gateway.cobrar(cobranca, chave);
                registro.registrarResultado(chave, resultado);
                return resultado;
            } catch (FalhaPermanenteException e) {
                throw e;                                       // erro permanente: nunca repete
            } catch (FalhaTransitoriaException e) {
                // efeito desconhecido: reconcilia ANTES de decidir repetir
                var remoto = consultarSeguro(chave);
                if (remoto.isPresent()) {
                    registro.registrarResultado(chave, remoto.get());
                    return remoto.get();                       // já processada no gateway: não repete
                }
                if (!haTempoParaOutraTentativa(tentativa, limite)) break;
                esperar(tentativa, limite);
            }
        }
        // sem resposta conclusiva: nunca inventa aprovação
        var pendente = new ResultadoCobranca.PendenteReconciliacao(chave);
        registro.registrarResultado(chave, pendente);
        return pendente;
    }

    private Optional<ResultadoCobranca> consultarSeguro(String chave) {
        try {
            return gateway.consultar(chave);
        } catch (FalhaTransitoriaException e) {
            // consulta falhou: não sabemos o estado. Repetir seria arriscado só se a chave
            // não fosse idempotente; com chave idempotente o gateway deduplica.
            return Optional.empty();
        }
    }

    private boolean haTempoParaOutraTentativa(int tentativa, long limite) {
        return tentativa + 1 < MAX_TENTATIVAS
                && limite - relogioMonotonico.getAsLong() > tetoEspera(tentativa).toNanos();
    }

    private void esperar(int tentativa, long limite) {
        // full jitter: sorteio entre 0 e o teto exponencial; sem segurar conexão durante a espera
        long teto = tetoEspera(tentativa).toNanos();
        esperador.dormir(Duration.ofNanos((long) (teto * jitter.getAsDouble())));
    }

    private Duration tetoEspera(int tentativa) {
        // min(maxDelay, base x 2^n), protegido contra overflow
        long fator = 1L << Math.min(tentativa, 20);
        return ATRASO_BASE.multipliedBy(fator).compareTo(ATRASO_MAXIMO) > 0
                ? ATRASO_MAXIMO : ATRASO_BASE.multipliedBy(fator);
    }
}
```

Observação: se a consulta devolve vazio por falha (não por "nunca recebido"), a repetição só é segura porque a chave idempotente faz o gateway deduplicar. Por isso o retry é condicionado ao gateway **honrar** `Idempotency-Key` (hipótese acima).

Adaptador de saída (timeouts explícitos, sem retry próprio):

```java
@Component
class GatewayPagamentoHttpAdapter implements GatewayPagamentoPort {

    private final RestClient cliente;

    GatewayPagamentoHttpAdapter(RestClient.Builder builder, GatewayProps props) {
        var fabrica = new JdkClientHttpRequestFactory();
        fabrica.setReadTimeout(Duration.ofMillis(1500));       // timeout por tentativa
        this.cliente = builder.baseUrl(props.url()).requestFactory(fabrica).build();
        // retry automático do cliente/SDK permanece DESLIGADO: o dono do retry é o use case
    }

    @Override
    public ResultadoCobranca cobrar(Cobranca c, String chave) {
        try {
            return cliente.post().uri("/cobrancas")
                    .header("Idempotency-Key", chave)
                    .body(c).retrieve().body(ResultadoCobranca.class);
        } catch (ResourceAccessException e) {                  // timeout/rede
            throw new FalhaTransitoriaException(e);
        } catch (HttpServerErrorException e) {                 // 5xx
            throw new FalhaTransitoriaException(e);
        } catch (HttpClientErrorException e) {                 // 4xx: não repete
            throw new FalhaPermanenteException(e);
        }
    }
    // consultar(...) análogo, GET /cobrancas?chave=...
}
```

### Provas (escritas antes da implementação; relógio, espera e jitter injetados, sem `sleep` real)

```java
class CobrarComRetryServiceTest {

    private final AtomicLong tempo = new AtomicLong();
    private final List<Duration> esperas = new ArrayList<>();
    private final GatewayFake gateway = new GatewayFake();     // fake com contador de efeitos reais
    private final RegistroFake registro = new RegistroFake();

    private CobrarComRetryService servico(Duration deadline) {
        return new CobrarComRetryService(gateway, registro, deadline, tempo::get,
                d -> { esperas.add(d); tempo.addAndGet(d.toNanos()); }, () -> 0.5);
    }

    @Test
    void timeoutComCobrancaJaProcessadaNaoDeveCobrarDeNovo() {
        gateway.processaMasExpiraResposta();                   // efeito ocorre, resposta se perde
        var r = servico(Duration.ofSeconds(5)).cobrar(cobranca());
        assertInstanceOf(ResultadoCobranca.Aprovada.class, r);
        assertEquals(1, gateway.efeitosReais());               // exatamente uma cobrança
    }

    @Test
    void timeoutSemEfeitoDeveRepetirComAMesmaChave() {
        gateway.expiraSemProcessarNaPrimeira();
        var r = servico(Duration.ofSeconds(5)).cobrar(cobranca());
        assertInstanceOf(ResultadoCobranca.Aprovada.class, r);
        assertEquals(1, gateway.efeitosReais());
        assertEquals(1, gateway.chavesDistintasUsadas());      // mesma chave nas duas tentativas
        assertEquals(List.of(Duration.ofMillis(50)), esperas); // full jitter 0,5 x teto de 100 ms
    }

    @Test
    void recusaDeNegocioNaoDeveSerRepetida() {
        gateway.falhaPermanente();
        assertThrows(FalhaPermanenteException.class, () -> servico(Duration.ofSeconds(5)).cobrar(cobranca()));
        assertEquals(1, gateway.chamadasDeCobranca());
    }

    @Test
    void naoDeveExcederMaximoDeTentativas() {
        gateway.sempreExpira();
        var r = servico(Duration.ofSeconds(5)).cobrar(cobranca());
        assertInstanceOf(ResultadoCobranca.PendenteReconciliacao.class, r);
        assertEquals(3, gateway.chamadasDeCobranca());
    }

    @Test
    void naoDeveDormirSeOBackoffConsomeODeadline() {
        gateway.sempreExpira();
        servico(Duration.ofMillis(50)).cobrar(cobranca());     // deadline menor que o teto do backoff
        assertTrue(esperas.isEmpty());
        assertEquals(1, gateway.chamadasDeCobranca());
    }

    @Test
    void duasExecucoesConcorrentesDaMesmaCobrancaGeramUmEfeito() throws Exception {
        // barreira + dois executores disputando a mesma chave; efeito único medido no gateway fake
    }

    @Test
    void falhaDeConsultaNaoDeveVirarSucesso() {
        gateway.sempreExpiraInclusiveConsulta();
        assertInstanceOf(ResultadoCobranca.PendenteReconciliacao.class,
                servico(Duration.ofSeconds(5)).cobrar(cobranca()));
    }
}
```

### Limites implementados

| Limite | Unidade | Escopo | Motivo |
|---|---|---|---|
| Deadline total | 5 s | operação lógica de cobrança | não segurar o chamador indefinidamente |
| Timeout de resposta | 1,5 s | por tentativa | I/O limitado derivado do restante |
| Tentativas | 3 (inclui a inicial) | operação lógica | impedir amplificação |
| Backoff | 100 a 400 ms, full jitter | entre tentativas | evitar rajada sincronizada no gateway |
| Pior caso | 3 x 1,5 s + 100 ms + 200 ms = 4,8 s, abaixo de 5 s | operação lógica | cabe no deadline, e se não couber encerra antes de dormir |

### Pendências e encaminhamentos

- Confirmar com o provedor que a chave idempotente é honrada e por quanto tempo é retida; sem isso, remover o retry automático e manter só `PENDENTE_RECONCILIACAO`.
- Job de reconciliação para cobranças `PENDENTE_RECONCILIACAO` (consulta por chave em taxa limitada), tabela `cobranca` com unicidade da chave e métrica de cobranças pendentes/repetidas.
- Se houver retry também em gateway/proxy/SDK, somar as camadas e manter só uma dona.
- Antes de declarar pronto: `java-revisor` em modo `auditoria` (obrigatório). Decisão de limites por criticidade do negócio pode ir ao `arquiteto-sistemas`.

## Pontuação
- Itens obrigatórios:
  - ✅ Resultado desconhecido: "timeout de resposta **não é rollback remoto** (o gateway pode ter cobrado)".
  - ✅ Chave persistida local e no provedor: "UUID gerado **uma vez** ... persistido antes da 1ª chamada" e o header `Idempotency-Key`.
  - ⚠️ Consultar antes de repetir: consulta ocorre, mas a tabela de decisões diz "se a consulta também falha, estado `PENDENTE_RECONCILIACAO`", enquanto o código (`consultarSeguro` → `Optional.empty()`) **repete a cobrança** sem consulta conclusiva. O próprio texto justifica com a chave ("com chave idempotente o gateway deduplica"). Decisão e código se contradizem.
  - ❌ Limite de deadline verificável: "Pior caso | 3 x 1,5 s + 100 ms + 200 ms = 4,8 s, abaixo de 5 s" ignora as consultas, que também levam até 1,5 s cada. O timeout é fixo (`setReadTimeout(1500)`) e não é "derivado do restante", como afirma a tabela. `haTempoParaOutraTentativa` só compara o tempo restante com o backoff, então uma nova tentativa pode começar com poucos ms de orçamento.
- Falha bloqueadora: não (há chave idempotente e consulta)
- Justificativa: a direção está correta e a prova é extensa. Porém o limite declarado (deadline de 5 s) não é garantido pelo código, e o caminho "consulta falhou" contradiz a decisão registrada. São erros técnicos relevantes, por isso a nota é 1.
