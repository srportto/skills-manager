## Saída bruta

Assumo Java 25, Spring Boot com JDBC/JPA e que as 10 conexões são o orçamento total reservado para esta instância. Virtual threads ajudam a atender muitas requisições I/O-bound sem depender de um pool fixo de threads; não aumentam as conexões disponíveis. Para proteger o banco, habilite virtual threads e limite a admissão ao acesso ao banco a 10 operações simultâneas. Rejeite cedo o excedente, em vez de manter uma fila de requisições sem limite.

```yaml
spring:
  threads:
    virtual:
      enabled: true
  datasource:
    hikari:
      maximum-pool-size: 10
      connection-timeout: 2000
```

Use um `Semaphore` singleton compartilhado pelos caminhos que acessam esse banco. A permissão cobre somente a operação/transação de banco e é liberada em `finally`:

```java
@Component
public class AdmissaoBanco {
    private final Semaphore permissoes = new Semaphore(10);

    public <T> T executar(Supplier<T> operacao) {
        if (!permissoes.tryAcquire()) {
            throw new BancoSaturadoException(); // Mapear para 503 no handler HTTP.
        }
        try {
            return operacao.get();
        } finally {
            permissoes.release();
        }
    }
}
```

O `tryAcquire()` sem espera torna explícito o comportamento ao chegar a 11ª operação concorrente: ela recebe saturação, e não fica acumulada numa fila ilimitada. Faça o acesso ao repositório dentro de `admissaoBanco.executar(...)`; não mantenha a permissão durante chamadas HTTP externas ou backoff. Mantenha também o timeout do pool como proteção de aquisição.

Se as 10 conexões forem o limite global do banco, ajuste o pool e o semáforo por instância para que a soma das réplicas, jobs e acessos administrativos permaneça dentro desse orçamento. Por exemplo, duas réplicas não podem ter pool de 10 cada para um orçamento global de 10. Monitore conexões ativas, pendentes e timeouts de aquisição.

Como prova, um teste concorrente com `CountDownLatch` e `AtomicInteger` deve disparar mais de 10 tarefas em virtual threads e demonstrar que o máximo de operações de banco simultâneas nunca passa de 10, que o excedente é rejeitado e que uma falha libera a permissão.
