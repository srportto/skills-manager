### Motivo (smells concretos)

### Código refatorado (trechos alterados; o restante da classe fica idêntico)

```java
public final class ConsumidorKafkaLimitado<V> implements AutoCloseable {
    private static final Duration PRAZO_REVOGACAO_PADRAO = Duration.ofSeconds(10);
    private static final Duration PRAZO_ENCERRAMENTO_WORKERS = Duration.ofSeconds(10);
    // ... campos, Estado, Conclusao inalterados ...

    // construtor curto: this(..., relogio, PRAZO_REVOGACAO_PADRAO);

    /** Um ciclo do laço de consumo; chame repetidamente na mesma thread. */
    public void ciclo(Duration timeoutPoll) {
        drenarConclusoes();
        commitar();
        ajustarPausas();
        enfileirarPorParticao(consumidor.poll(timeoutPoll));
        despachar();
        ajustarPausas();
    }

    private void enfileirarPorParticao(ConsumerRecords<String, V> registros) {
        for (ConsumerRecord<String, V> registro : registros) {
            var particao = new TopicPartition(registro.topic(), registro.partition());
            estados.computeIfAbsent(particao, p -> new Estado<>()).pendentes.addLast(registro);
        }
    }

    private void aplicar(Conclusao<V> conclusao) {
        emVoo--;
        Estado<V> estado = estados.get(conclusao.particao());
        // Conclusão de partição já revogada — ou de uma entrega anterior à reatribuição da partição a este membro —
        // é descartada: o offset não é commitado aqui e o registro atual da partição segue seu próprio fluxo.
        if (estado == null || estado.emAndamento != conclusao.registro()) return;
        estado.ocupada = false;
        estado.emAndamento = null;
        if (conclusao.resultado().decisao() == ConsumoControlado.Decisao.CONFIRMAR) {
            registrarSucesso(conclusao, estado);
            return;
        }
        registrarFalha(conclusao, estado);
    }

    private void registrarSucesso(Conclusao<V> conclusao, Estado<V> estado) {
        estado.pendentes.pollFirst();
        estado.tentativas = 0;
        estado.ultimoErro = null;
        aCommitar.put(conclusao.particao(), new OffsetAndMetadata(conclusao.registro().offset() + 1));
    }

    private void registrarFalha(Conclusao<V> conclusao, Estado<V> estado) {
        estado.tentativas++;
        estado.ultimoErro = conclusao.resultado().erro();
        estado.proximaTentativa = relogio.getAsLong() + pausaEntreTentativasNanos;
    }

    private void despachar() {
        long agora = relogio.getAsLong();
        for (var entrada : estados.entrySet()) {
            if (emVoo >= limiteEmVoo) return;
            if (prontaParaDespacho(entrada.getValue(), agora)) iniciarTrabalho(entrada.getKey(), entrada.getValue());
        }
    }

    private boolean prontaParaDespacho(Estado<V> estado, long agora) {
        return !estado.ocupada && !estado.pendentes.isEmpty() && agora >= estado.proximaTentativa;
    }

    private void iniciarTrabalho(TopicPartition particao, Estado<V> estado) {
        ConsumerRecord<String, V> registro = estado.pendentes.peekFirst();
        boolean quarentenar = estado.tentativas >= maxTentativas;
        Exception causa = estado.ultimoErro;
        estado.ocupada = true;
        estado.emAndamento = registro;
        emVoo++;
        workers.execute(() -> conclusoes.add(new Conclusao<>(particao, registro,
                quarentenar ? controle.quarentenar(registro, causa) : controle.consumir(registro))));
    }

    /** Antes de perder a partição: espera (limitado) o trabalho em andamento e commita o que concluiu. */
    private void aoRevogar(Collection<TopicPartition> particoes) {
        aguardarTrabalhoEmAndamento(particoes);
        Map<TopicPartition, OffsetAndMetadata> revogados = descartarEstadoRevogado(particoes);
        if (!revogados.isEmpty()) consumidor.commitSync(revogados);
    }

    private void aguardarTrabalhoEmAndamento(Collection<TopicPartition> particoes) {
        long limite = System.nanoTime() + prazoRevogacao.toNanos();
        try {
            while (algumaOcupada(particoes)) {
                long restante = limite - System.nanoTime();
                if (restante <= 0) break;
                Conclusao<V> conclusao = conclusoes.poll(restante, TimeUnit.NANOSECONDS);
                if (conclusao != null) aplicar(conclusao);
            }
        } catch (InterruptedException erro) {
            Thread.currentThread().interrupt();
        }
    }

    private boolean algumaOcupada(Collection<TopicPartition> particoes) {
        return particoes.stream().map(estados::get).anyMatch(e -> e != null && e.ocupada);
    }

    private Map<TopicPartition, OffsetAndMetadata> descartarEstadoRevogado(Collection<TopicPartition> particoes) {
        var revogados = new HashMap<TopicPartition, OffsetAndMetadata>();
        for (TopicPartition particao : particoes) {
            OffsetAndMetadata offset = aCommitar.remove(particao);
            if (offset != null) revogados.put(particao, offset);
            estados.remove(particao);
        }
        return revogados;
    }

    @Override
    public void close() throws InterruptedException {
        workers.shutdown();
        if (!workers.awaitTermination(PRAZO_ENCERRAMENTO_WORKERS.toSeconds(), TimeUnit.SECONDS)) workers.shutdownNow();
        drenarConclusoes();
        commitar();
    }
}
```

Inalterados: `assinar`, `commitar`, `drenarConclusoes`, `ajustarPausas`, `emVoo()`, construtores (exceto o literal) e a Javadoc da classe.

### Invariantes preservados (conferidos linha a linha)
- Thread única do `Consumer`: nada novo toca o consumidor fora de `ciclo`/callbacks do rebalance; workers continuam só empurrando em `conclusoes`.
- Ordem do `ciclo` intacta: drenar, commitar, pausas, poll, despachar, pausas. Ordem por partição mantida (um registro por partição por vez, `peekFirst`; só `pollFirst` ao confirmar).
- Commit só após conclusão confirmada e só no `commitar()`/revogação; `aCommitar` continua sendo limpo só depois do `commitSync`.
- `emVoo--` continua antes da checagem de conclusão obsoleta; conclusão de partição revogada/reatribuída segue descartada sem commit.
- Falha: `tentativas++`, `ultimoErro`, `proximaTentativa` iguais; esgotadas as tentativas continua indo para `quarentenar`, e falha da quarentena não commita.
- Revogação: mesma espera limitada (`System.nanoTime`, mesmo `catch` com re-interrupt), mesmo descarte de estado/`aCommitar`, mesmo `commitSync` único; `onPartitionsLost` continua só removendo estados.
- `despachar`: mesma condição de parada (`emVoo >= limiteEmVoo` antes de cada partição), mesma captura de `registro`/`quarentenar`/`causa` antes de marcar `ocupada`; mesma iteração do `HashMap`.
- Constantes têm os mesmos valores (10 s e 10 s).

### Achados fora do escopo (não alterei: são correção de bug, não refactoring)
- `onPartitionsLost` remove `estados`, mas não remove entradas de `aCommitar` dessas partições; um offset pendente pode ser commitado depois por `commitar()` para uma partição que o membro já não possui. Vale tarefa separada para `java-construtor`, com teste que reproduza.
- Em `aoRevogar`, vencido o prazo, o trabalho ainda ativo continua no worker; sua conclusão tardia é descartada corretamente, mas o efeito pode ocorrer sem commit (reprocessamento), o que o contrato de idempotência já assume.
