**application** — `@Transactional` mora no use case (nunca no controller/domain), `readOnly` na classe e escrita sobrescrita por método:

```java
// application/usecase/ProdutoService.java
@Transactional(readOnly = true)
public class ProdutoService implements CriarProdutoUseCase, BuscarProdutoUseCase,
        ListarProdutosUseCase, AtualizarProdutoUseCase, ExcluirProdutoUseCase {

    private final ProdutoRepositoryPort repositorio;

    public ProdutoService(ProdutoRepositoryPort repositorio) {
        this.repositorio = repositorio;
    }

    @Override
    @Transactional
    public Produto executar(CriarProdutoUseCase.NovoProduto comando) {
        return repositorio.salvar(new Produto(null, comando.nome(), comando.preco()));
    }

    @Override
    public Produto buscar(Long id) {
        return repositorio.buscarPorId(id)
                .orElseThrow(() -> new BusinessException("Produto não encontrado: " + id));
    }

    @Override
    public List<Produto> listar(int pagina, int tamanho) {
        return repositorio.listar(pagina, tamanho);
    }

    @Override
    @Transactional
    public Produto atualizar(Long id, String nome, BigDecimal preco) {
        buscar(id);   // auto-invocação só de leitura: a transação já é a do método atual
        return repositorio.salvar(new Produto(id, nome, preco));
    }

    @Override
    @Transactional
    public void excluir(Long id) {
        if (!repositorio.existePorId(id)) {
            throw new BusinessException("Produto não encontrado: " + id);
        }
        repositorio.excluirPorId(id);
    }
}

// infrastructure/config/BeansConfig.java — o bean do caso de uso é declarado aqui (padrão do esqueleto)
@Configuration
class BeansConfig {
    @Bean
    ProdutoService produtoService(ProdutoRepositoryPort repositorio) {
        return new ProdutoService(repositorio);
    }
}
```

**infrastructure/persistence** — entidade enxuta (sem `@Data`, igualdade só pelo id, `@Version` contra lost update em PUT concorrente):

```java
@Entity
@Table(name = "produtos")
@Getter @Setter @NoArgsConstructor
class ProdutoEntity {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @Column(nullable = false, length = 80)
    private String nome;
    @Column(nullable = false, precision = 12, scale = 2)
    private BigDecimal preco;
    @Version
    private long versao;

    @Override public boolean equals(Object outro) {
        return outro instanceof ProdutoEntity p && id != null && id.equals(p.id);
    }
    @Override public int hashCode() { return getClass().hashCode(); }
}

interface ProdutoJpaRepository extends JpaRepository<ProdutoEntity, Long> { }

@Mapper(componentModel = "spring")
interface ProdutoMapper {
    Produto paraDominio(ProdutoEntity entidade);
    @Mapping(target = "versao", ignore = true)
    ProdutoEntity paraEntidade(Produto produto);
}

@Repository
class ProdutoRepositoryAdapter implements ProdutoRepositoryPort {

    private static final int TAMANHO_MAXIMO = 100;   // teto de página: cliente não pede 1 milhão de linhas

    private final ProdutoJpaRepository jpa;
    private final ProdutoMapper mapper;

    ProdutoRepositoryAdapter(ProdutoJpaRepository jpa, ProdutoMapper mapper) {
        this.jpa = jpa;
        this.mapper = mapper;
    }

    @Override
    public Produto salvar(Produto produto) {
        return mapper.paraDominio(jpa.save(mapper.paraEntidade(produto)));
    }

    @Override
    public List<Produto> listar(int pagina, int tamanho) {
        var pageable = PageRequest.of(pagina, Math.min(tamanho, TAMANHO_MAXIMO), Sort.by("id"));
        return jpa.findAll(pageable).map(mapper::paraDominio).getContent();
    }
    // buscarPorId, existePorId, excluirPorId delegam ao jpa
}
```

Observação sobre PUT: com `@Version`, para o lock otimista valer o adapter deve, na atualização, carregar a entidade pelo id e copiar nome/preço nela (em vez de dar `save` numa entidade nova montada pelo mapper). Violação da unique de `nome` ou `OptimisticLockingFailureException` são tratadas no `ApiExceptionHandler` como 409 (o flush acontece no commit; `try/catch` em volta do `save` não pega).

**infrastructure/web** — DTOs são `record`, validados na borda; controller fino atrás da `port/in`:

```java
public record ProdutoRequest(@NotBlank @Size(max = 80) String nome, @NotNull @Positive BigDecimal preco) { }
public record ProdutoResponse(Long id, String nome, BigDecimal preco) { }

@RestController
@RequestMapping("/produtos")
@Validated
class ProdutoController {

    private final CriarProdutoUseCase criar;
    private final BuscarProdutoUseCase buscar;
    private final ListarProdutosUseCase listar;
    private final AtualizarProdutoUseCase atualizar;
    private final ExcluirProdutoUseCase excluir;
    // construtor com as cinco portas de entrada

    @PostMapping
    ResponseEntity<ProdutoResponse> criar(@Valid @RequestBody ProdutoRequest req) {
        var produto = criar.executar(new CriarProdutoUseCase.NovoProduto(req.nome(), req.preco()));
        return ResponseEntity.created(URI.create("/produtos/" + produto.id())).body(paraResposta(produto));
    }

    @GetMapping("/{id}")
    ProdutoResponse buscar(@PathVariable Long id) { return paraResposta(buscar.buscar(id)); }

    @GetMapping
    List<ProdutoResponse> listar(@RequestParam(defaultValue = "0") @Min(0) int pagina,
                                 @RequestParam(defaultValue = "20") @Min(1) @Max(100) int tamanho) {
        return listar.listar(pagina, tamanho).stream().map(this::paraResposta).toList();
    }

    @PutMapping("/{id}")
    ProdutoResponse atualizar(@PathVariable Long id, @Valid @RequestBody ProdutoRequest req) {
        return paraResposta(atualizar.atualizar(id, req.nome(), req.preco()));
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    void excluir(@PathVariable Long id) { excluir.excluir(id); }

    private ProdutoResponse paraResposta(Produto p) { return new ProdutoResponse(p.id(), p.nome(), p.preco()); }
}
```

Erros pelo `ApiExceptionHandler` do esqueleto (Problem Details): `@Valid` falho gera 400, `BusinessException` gera 422, `ApplicationException` gera 500; acrescentar 409 para conflito (unique/`@Version`). "Produto não encontrado" como `BusinessException` (422) segue o padrão da skill; se preferir 404, crie `RecursoNaoEncontradoException` em `domain/exception` e mapeie no handler.

## Pontuação
- Itens obrigatórios:
  - ✅ Solução simples: "fica de fora, de propósito, ... broker/fila, cache Redis, WebFlux, Resilience4j/circuit breaker".
  - ✅ Paginação: "`max-page-size: 100`", `@Max(100)` no controller e teto no adapter.
  - ✅ Timeout: "`connection-timeout: 2000`" e "`jakarta.persistence.query.timeout: 3000`".
  - ❌ Payload: "Payload | 1 MB | requisição | limite de borda" via `server.tomcat.max-http-form-post-size: 1MB`. Essa propriedade só limita formulários `application/x-www-form-urlencoded`, não o corpo JSON da API, então o limite declarado não existe na prática. `@Size(max = 80)` limita o campo depois do parse, não o tamanho da requisição.
  - ✅ Sem infraestrutura distribuída.
- Falha bloqueadora: não
- Observação: o texto reconhece que `@Version` exige "carregar a entidade pelo id e copiar nome/preço", mas o adapter apresentado faz `save` de entidade nova com `versao = 0`. Após o primeiro update, isso gera conflito em todo PUT.
- Justificativa: proporcionalidade, paginação e timeouts estão corretos, mas o limite de payload, item obrigatório, usa um mecanismo que não se aplica a JSON. Nota 1.
